# CP Meta

本文件定义控制平面文档的元规则。

控制平面是 agent coding、用户意图和 project code 交会的界面：它不替代代码、memory 或需求文档，而是把当前目标、边界、核心约束和任务推进状态组织成 agent 可执行的上下文。

控制平面建立规范和目标，约束 agent 的行动边界，让实现按可验证步骤稳步推进；真正的数据、业务规则和运行时行为仍以 project code 中的权威入口为准。

## Naming

- 控制平面文件统一使用 `cp-*.md` 命名；`cp` 是 control plane 的固定缩写。
- `cp-meta.md` 是元控制平面；其他 `cp-*.md` 是实例控制平面。
- 实例名应表达被控制的目标边界，例如 `cp-scene.md`、`cp-message-center.md`。
- 新增实例前先判断是否能并入现有控制平面；只有当 scope、核心规则或任务板需要独立维护时才新增。

## Structure

实例控制平面优先保持以下结构：

- `Control Plane Role`：说明该平面控制什么、为何存在、与其他平面的关系。
- `Meta Reference`：引用本文件，并声明何时调用本平面。
- `Scope`：冻结主作用域、相关代码和不在本平面内解决的事项。
- `Core Rules`：保留高频约束 agent 行为的核心规则；可包含调用顺序、边界冻结、验证、暂停询问、沉淀 memory 等操作规则。
- `Task Board`：维护当前任务区，主要采用 checkbox 列表；复杂任务可使用树状 checkbox；任务项不添加日期或时间戳前缀。

固定结构区允许按信息密度动态选择表达形式，但必须服务于清晰和最小必要上下文：

| Section | 允许组织方式 | 约束 |
| --- | --- | --- |
| `Control Plane Role` | 自然段为主；必要时可加短列表或小表格 | 优先用几个自然段说明控制对象、存在理由和相邻 CP 关系 |
| `Meta Reference` | 短列表、分级列表 | 保持简洁，只写调用入口、相关 skill 和读取顺序 |
| `Scope` | 短列表、分级列表 | 保持简洁，最多到分级列表；不要拆出多个章节 |
| `Core Rules` | 短列表、分级列表、表格或少量小章节 | 可按规则类型动态拆分，目标是让 agent 和人以最少但合理的阅读成本理解约束 |
| `Task Board` | checkbox、树状 checkbox、表格或按阶段/状态拆小章节 | 可随任务复杂度动态调整，目标是清晰表达当前可执行队列、暂缓项和验收状态 |

`Task Board` 之后允许 agent 根据当前任务动态新增、更新或删除章节，用于承载设计草案、阶段记录、临时决策和下一步执行输入。动态章节的表达方式不设固定模板，可灵活使用 checkbox、树状 checkbox、表格、按阶段/状态拆分的小章节或其他更合适的形式；相比固定结构区，它可以更详细、更灵活，但仍以清晰、必要、易于 agent 和人理解为准。动态章节不应倒灌成固定结构；若其中内容变成长期规则，应沉淀到 memory 或提升到 `Core Rules`。

## Invocation

- 非小规模文案、样式微调或单文件补丁任务开始前，agent 先读本文件，再读命中的实例控制平面。
- 若任务同时命中多个实例，先读本文件，再按最上位边界到最具体边界读取实例。
- 创建或扩展控制平面时，自动使用 `create-control-plane` skill。
- 任务级收尾、阶段级完成、控制平面上下文膨胀或用户要求精简 cp 时，自动使用 `compact-control-plane` skill。
- 实例控制平面只能收束任务边界，不得把任务扩大为无边界扫描、全量重构或顺手整理。
- 与更高优先级规则或 skill 指令冲突时，按更高优先级规则执行；控制平面只补充任务上下文。

## Update Rules

- 每个实例分为固定结构区和动态任务区。
- 固定结构区只包含 `Control Plane Role`、`Meta Reference`、`Scope`、`Core Rules`、`Task Board`；除规则冲突、规则过时或控制平面本身需要调整外，非必要不更改 `Task Board` 之前的章节。
- `Task Board` 及其后续内容属于动态任务区，可以根据当前任务更新、新增章节或删除过时明细。
- 识别到临界阶段时，必须使用 `compact-control-plane` 压缩当前任务区上下文：任务级收尾应把可复用结论沉淀到相关 memory 后删除历史明细；阶段级完成时，若已完成 checkbox 和 `Task Board` 后动态章节不再承载下一阶段必要上下文，应直接删除；只保留下一阶段仍需要的任务背景、未决问题和必要设计上下文。
- 当前任务区产生的可复用规则、决策或坑点应沉淀到相关 memory；一次性进度、临时 TODO、会随代码频繁变化的现状事实和已失效方案不得沉淀为规则。
- 仍需高频约束 agent 行为的规则必须保留在实例 `Core Rules`，不得只放入 memory 后从控制平面移除。

## Operating Defaults

- 开始非小规模改动前先冻结最小边界：当前调用方、入口点、本次改动要暴露的最小公共 API。
- 先读 memory 入口，再读与当前 scope 直接相关的 memory 文件；若 memory 与当前代码或控制平面冲突，以当前代码、高优先级规则和当前控制平面为准。
- 若触发多个自动行为，默认顺序为：读取元控制平面、读取实例控制平面、冻结边界、查找 memory、使用必要 skill、更新任务板、改动、验证、按需沉淀 memory、按需精简控制平面。
