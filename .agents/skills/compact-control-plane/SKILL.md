# Compact Control Plane

## 自动调用时机

- 任务级收尾：当前任务已完成、验证结束或用户明确要求收尾。
- 阶段级完成：一组子任务完成，但下一阶段仍需要部分背景、未决问题或设计输入。
- 控制平面膨胀：`Task Board` 之后累计大量过程记录、过期 TODO、临时方案或已完成明细。
- 上下文失真：动态章节中的代码现状、边界描述或计划已明显依赖旧代码。
- 用户要求：出现“精简 cp / 压缩控制平面 / 清理任务板 / 清理历史上下文”等意图。

## 精简流程

1. 读取 `.cp/cp-meta.md`、目标 `.cp/cp-<scope>.md` 和同目录 `cpm-<scope>.md`；CPM 不存在时按需创建。
2. 冻结本次精简范围：只处理 `Task Board` 及其后动态章节；除规则冲突或用户要求外，不改 `Task Board` 之前的固定结构区。
3. 分类动态内容：
   - 长期规则、决策、坑点：写入同目录同 scope 的 `cpm-<scope>.md`，或提升到 `Core Rules`。
   - 下一阶段仍需要的任务背景、未决问题、设计输入：保留并压缩。
   - 已完成过程、临时 TODO、已失效方案、会随代码频繁变化的现状事实：删除；不要改成归档 checkbox。
4. 更新 `Task Board`：
   - 活跃项保留为 checkbox。
   - 复杂任务可用树状 checkbox、状态分组、小章节或表格；选择最清晰且最少必要上下文的表达方式。
   - 任务项不添加日期或时间戳前缀。
   - 已完成项仅在仍需下一阶段追踪时短暂保留；阶段结束且内容可移除时直接删除。
   - 用户明确表示后续单独提出、暂不实现或等待进一步指示的事项，应单独分组为暂缓/待指示，不混入当前可执行队列。
5. 精简 `Task Board` 后的动态章节：
   - 只保留下一阶段仍需要的内容。
   - 动态章节可新增、改名、合并或删除。
6. 输出时说明写入了哪些 CPM 记忆、删除了哪些历史明细、仍保留哪些下一阶段上下文。

## 判断规则

- 仍需高频约束 agent 行为的规则必须保留在实例 `Core Rules`，不得只放入 CPM 后从控制平面移除。
- 可复用但不需要高频提醒的规则、决策或坑点应沉淀到同 scope CPM。
- 一次性进度、临时 TODO、旧方案、过时代码现状和可由当前代码重新发现的事实不得写入 CPM。
- 阶段结束后，若完成项和 `Task Board` 后相关段落不再提供下一阶段必要输入，应删除而不是保留带日期的完成记录。
- 不为了“整洁”删除下一阶段仍必须依赖的业务输入、未决问题或设计约束。
- 如果无法判断某条内容是规则还是临时事实，先保留短句并标注待确认；不要擅自沉淀为规则。
