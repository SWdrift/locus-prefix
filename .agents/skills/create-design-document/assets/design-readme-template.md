# 设计文档

本目录集中维护已经确定、需要跨任务复用的具体设计，是项目设计的权威入口。未收敛草案、活跃任务、实现快照和外部参考资料不在此处维护。

## 管理规则

- 用户未指定位置时，设计目录默认为项目根下的 `document/design/`；项目已有明确约定时沿用现有目录。
- 文件名使用简短、具体、人类可读的主题名；默认格式为 `<主题>设计.md`。
- 一套具体设计对应一个 Markdown 文档；同一规则只在一份权威文档中完整定义。
- 其他文档只保留自身边界所需的摘要，并使用可点击的 Markdown 相对链接指向权威设计。
- 跨文档复用优先链接到权威文档的具体标题，不重新描写整段内容。
- 设计文档使用可链接的标题组织内容；标题按主题边界和导航需要灵活设置，避免碎片化标题和无标题长文。
- 具体设计开头必须包含“简述”和“职责”：前者说明主题与目的，后者说明本文负责与不负责的边界；后续章节按内容需要自由编排。
- “简述”和“职责”后的结构自由，但同一项目、同一层级文档应保持命名、层级和表达风格一致。
- 被引用文档尚不存在时必须标注“待补充”，不能写成已经存在的文档。
- 设计必须区分当前实现、确定的目标设计和待决问题；待决内容不能作为确定结论落盘。
- 文档至少明确目标、范围、非目标、关键约束、关键流程或模型、异常与边界、验证口径；不适用章节直接省略。
- 设计变更时，同步检查相关代码、可执行契约、测试、引用和本 README；不得长期保留两套口径。
- README 只管理本目录的规则、权责和索引，不承载具体设计正文。

## 文档权责

- 设计意图、稳定边界、关键规则和验证口径：本目录对应的权威设计文档。
- 当前实现和逐项代码事实：代码、可执行契约及工程 README。
- 架构决策过程和备选方案取舍：ADR。
- 活跃任务、阶段进度和临时草案：控制平面、任务板或 issue。
- 外部输入资料：项目约定的 reference 目录，保留来源原貌，不作为本系统确定设计。

## 更新规则

- **新增：** 先确认无主题重叠，再登记叙事权责和设计列表。
- **修改：** 同步更新受影响的引用、契约和验证口径。
- **拆分或合并：** 明确迁移后的唯一权威位置，更新全部相对链接，不保留重复正文。
- **替代：** 在旧文档中指向新权威文档；旧文档不再承担现行规则时删除旧索引项。
- **删除：** 确认没有有效引用或独立职责后删除，并清理叙事权责和设计列表。
- **建立子目录：** 仅用于多份稳定、边界一致的专题设计；子目录必须有自己的 `README.md`，且不得与上级 scope 重叠。
