# 可分叉探索、派生判断与有界承诺不是同一种历史

`commit`引用包含本轮研究、实验与证据的标签`10-semantic-boundaries`，不使用自引用SHA。检出该标签后按下列命令复现。关联[案例1](../cases/1-heterogeneous-engineering-workspace.md)情境4–7。

## 1. 这轮改变了什么

**研究单位从“给对象补哪些元机制”改成“跨边界需要保持什么保证”。** 这不是认定对象、简单Core或JS不再有价值，而是撤销它们作为所有方案默认前提的地位。

[研究总览](../paradigm-study.md)给出十项假设逐项反方、历史脉络与四种竞争构想；[因果历史专题](../causal-history-study.md)和[执行/互操作专题](../execution-history-study.md)提供关键机制、一手来源、真实消费代码或标明未本机运行的流程。本轮没有创建公共包、注册表、统一图、运行时或新DevOps设施。

本轮不是新范式已经成立的证明。得到的是值得继续检验的表达方向：**知识和解释可分叉、派生判断可撤回，动作只对明确的范围及执行契约承诺。** 其中CRDT、SQL、CALM、capability、持久工作流都是已有思想，不能包装为Locus发明。

## 2. 有实质差异的能力与边界

### 保留因果分歧改变了可检查的事物，不保证领域结论正确

主线程独立运行[实验15](../../tests/15-causal-history/scenario.js)，使用Automerge 3.5.0，而非手写CRDT。两个共同祖先上的离线修订合并后，正反顺序得到相同文档，保留两个head及三项字段冲突；`Counter`累积为3。对照中的whole/field-LWW也收敛，却丢弃另一分支的反驳；普通JS若保留全部版本及祖先也能检测分歧，不能将本fixture的快照设计说成语言本身的上限。

关键反例不是“CRDT比JSON好”：本fixture默认读取的claim来自反驳者，status/evidence来自支持者，形成两位作者都未提交过的组合。结构校验通过，领域含义却冲突。另一个不同字段的并发修订合并出`validFrom=40 > validUntil=30`，`getConflicts`为空，领域不变量检查才拒绝。**字段冲突完整与领域不变量有效是不同保证。**

`save/load`保留heads、冲突及Counter类型；JSON投影再导入只剩新的一次变更，冲突为0，Counter成为普通数，后续increment抛出TypeError。这将[结论1的“JSON无损投影”](1-core.md#实验-1身份与-json-边界)进一步限定为其显式编码的数据契约：字段值可序列化，不表示原有系统语义无损。

合并前本地无冲突、不知道远端head时`getMissingDeps`为空，不能据此发现离线反驳。冒用白名单actor ID的变更通过本实验策略，说明actor ID不是作者认证。[精选观察摘要](../evidence/10-semantic-boundaries/causal-history.json)保留这些结果。实验15的restart仅为模拟日志；外部副作用边界由实验16真实文件写入观察，不混称实际重启。

### 关系可以推导，变化可以传播，但外部事实仍需摄取

[实验16](../../tests/16-derived-decisions/scenario.js)真实运行Vue reactivity与Node SQLite。追加反证后，原生函数重新计算与Vue派生均撤回许可；保存的布尔快照不变。SQL用`NOT EXISTS`推导eligible关系，不要求显式维护每一条派生边。

第二SQLite连接提交反证后，直接查询已为空，`computed(SQL查询)`却仍保留repair。显式revision摄取信号后，桥接computed才返回空。**依赖跟踪只覆盖图内变化**；不是把任意读取包进computed就得到跨系统变化传播。

这支持原生函数作为强基线，也支持响应式/查询机制具有不同组合方式；没有测量多消费者负载下的重算成本、维护时间或Agent成功率，不能给总体优劣排名。

### 本地串行化不等于可撤销的端到端动作

同一实验真实打开两个SQLite连接：`BEGIN IMMEDIATE`使第二writer收到`SQLITE_BUSY`；第一个本地意图先提交，反证随后提交，新的意图插入为0。但旧意图依然实际写出`executed:repair`文件。[观察摘要](../evidence/10-semantic-boundaries/derived-decisions.json)保留运行版本与结果。

这否定“数据库事务自动保证后到反证阻止未执行动作”，不否定SQLite事务本身，也不证明所有旧意图执行都不合法：如果接纳就是不可撤销的限额grant，旧意图完成可以正确；如果契约要求撤销未执行动作，则执行器还必须参与。**证据充分性、授权有效性、动作是否发生不可合成一个status。**

[MCP 2025-11-25取消规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks#task-cancellation)也明确允许任务状态cancelled而执行继续；这是文献中的对应边界，不是本轮运行了MCP。

## 3. 原假设的处理

| 原判断或推进倾向 | 本轮处理 | 证据边界 |
| --- | --- | --- |
| 描述、引用、执行与组合应默认交给JS/ESM | 限定为一条候选路线；SQL/CRDT/持久执行语义可以是能力来源，而非JS对象的附属元数据 | 实验15/16与执行专题；不修改结论7历史文本 |
| 身份与可见字段足够描述跨时空知识 | 区分heap引用、领域名字、版本、因果历史；投影必须说明保留什么保证 | 因果历史专题；不声称解决外部设施认证 |
| 保持单源知识就解决持续演化 | 单源消除一类重复声明，不自动处理并发分歧、输入完整性或外部动作撤销 | 限定结论9，不推翻其受控门禁行为 |
| append-only/CRDT即可使判断无协调 | 存储增长不意味着否定查询单调；同时保留escrow/不变量保持操作这一强反方 | [CALM](https://arxiv.org/html/1901.01930v1)、[I-confluence](https://www.vldb.org/pvldb/vol8/p185-bailis.pdf)、[bounded counter](https://arxiv.org/html/1503.09052v1)；这些论文系统本轮未运行 |
| 简单Core天然降低总体成本 | 不成立为普遍规则；复杂数据库、工作流或capability运行时可以承担难题 | 历史比较有机制依据，没有等价职责总成本实测 |
| 不造Core就是研究成功 | 拒绝该评价；应看是否产生可表达/可组合/可验证的新能力及付出的责任 | 本轮保留并发与派生行为证据，长期价值仍需后续实证 |

这些是对[结论1](1-core.md)、[7](7-api-expression.md)、[8](8-api-review.md)、[9](9-workspace-evolution.md)的支持/限定关系，不静默删除错误或改写案例。继续保留[结论5](5-release-lineage.md)/[6](6-operations-truth-loop.md)关于声明、实际见证与生效状态的区分。本轮不把旧87项通过当新证据。

## 4. 竞争构想与剩余矛盾

1. **无中心的可检查组合**：原生模块/协议/文件保留身份与生命周期，Agent临时构造消费；跨任务失效、恢复和协议适配由组合承担。
2. **因果协作空间**：成熟CRDT保存离线分歧与因果历史，执行层不把可见winner当唯一真理；需要共同历史、冲突策略和有语义的持久化。
3. **查询/变化驱动的决策空间**：关系由事实推导，图内依赖自动失效，本地事务约束意图；外部摄取、证据范围与执行器仍是显式边界。
4. **外部引擎主导的可重放工作**：构建/协调/工作流或capability运行时提供本身的语义，JS可退为前端；代价是运行时、确定性/版本约束及领域适配。这一路线仅做一手资料研究，未本机运行Nix/Temporal/Goblins。

没有预选赢家。值得保留的矛盾是：

- 离线探索越自由，某次不可撤回动作越不能假设已听到一切；要求全局在线又可能损害流畅。有限授权/不变量保持操作可改变问题，而不只是加强门禁。
- 分歧可合并不代表应自动决策；永远人工仲裁又可能使协作阻塞。冲突处理本身需要领域语义。
- 联邦保留差异，也增加版本关联与摄取责任；统一引擎减少局部责任，却可能要求迁移原有语义。两者都是实际成本，不能靠API长度判断。
- Agent能生成适配，不因此自动获得幂等性、认证或重放兼容性。本轮没有新增Agent行为评估，不能宣称Agent已使稳定接口不再必要。

## 5. 复现与未覆盖面

```sh
pnpm install --offline --ignore-scripts --frozen-lockfile
node --test tests/15-causal-history/demo.test.js tests/16-derived-decisions/demo.test.js
node tests/16-derived-decisions/scenario.js

```

首次检出缺缓存时去掉`--offline`；所有依赖在根devDependencies并由lockfile锁定。实验16已观察环境：Node v24.19.0、Vue reactivity 3.5.44、SQLite 3.53.3。它在工作区temp内真实写数据库与actuator文件并关闭清理，不触碰外部设施。

本轮实际验收：离线frozen安装成功；两个scenario均由主线程实际运行；`pnpm test`共89项通过、0失败、0跳过。随后删除实验15中模拟日志、报告文案、字节大小及重复投影的偶然断言，最终单独运行实验15/16：2项通过、0失败；其后未改行为代码。五份入口/研究Markdown的90个本地链接、引用标签、必需front matter字段及两份证据JSON检查通过。89是全仓测试总数，本轮增加两个综合实验断言入口，不是89项独立范式证明。

两项实验都是有界语义反例；不证明生产、多机、任意作者认证、长期维护收益，也没有实现自动安全授权。历史资料中明确区分成熟工程实现、研究原型与实验性规范；Codd全文访问失败的限制保留在总览，不伪称读完不可达来源。

## 6. 下一项最有价值的分歧

把离线反证在本地接纳前后分别送达，比较两种真正不同的契约：可撤销决策＋支持版本前提的执行器，以及不可撤销的有限授权＋保持不变量的操作。检验冲突/授权版本是否实际改变动作，而不是再加一个通用evidence字段。另一独立方向是运行成熟持久工作流的崩溃恢复，验证控制流历史与知识修订能否各自演化。

这不是本轮未完成的框架功能，而是由当前实验边界产生的新研究问题；本轮交付本身不依赖它们成立。
