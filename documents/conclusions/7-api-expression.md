# 原生组合优先，显式观测边界仍待证明通用价值

`commit` 引用包含本轮实验、研究记录与结论的标签 `7-api-expression`，可通过该标签复现。

关联[案例1](../cases/1-heterogeneous-engineering-workspace.md)的接入、专用接口、替换、知识复用问题。完整[阶段A草案、B变化推演及C成本记录](../api-expression-study.md)先设计消费代码再实现；[实验13](../../tests/13-api-expression/demo.test.js)复用实验11设施和既有领域包，不修改历史实现、案例或结论。

## 已验证事实

1. **普通组合已能跨设施接口复用。** `accept(inspect, {expected, artifact})` 同时使用发布判定和请求结果。四条消费路径都经过角色接口→直接HTTP、gateway-a→gateway-b的变化，组合函数无需修改。设施适配仍由具体边界承担，新增机制没有消除它。
2. **模块引用与外部事实必须分开。** 四方案均观察到同制品审计 `consistent`，请求仍502；清空覆盖文件仍502，重启才200。实例更换后重新观测，不能复制旧结果。支持并限定[结论5](5-release-lineage.md)与[结论6](6-operations-truth-loop.md)，不增加新的发布保证。
3. **函数身份说明不是自动发现。** A 可按显式导出查询四项说明；新函数未关联时返回无说明。普通导出对象能表达同样信息。没有验证任意Agent能可靠解释或遵守说明。
4. **动态跟随不是透明替换。** 基线和A缓存的方法仍访问gateway-a；B的显式函数边界及C的动态方法访问gateway-b。C中代理外闭包仍访问gateway-a，说明只拦截经过代理的调用。没有增加递归代理挽救它。
5. **显式检查能够拒绝部分错误归属。** B拒绝旧实例证据、观测返回期间切换目标、声明B却实际访问A的闭包。其失败事件归属开始时subject。C也在调用开始时固定日志来源，但不拒绝期间变化；不是把日志记下就自动获得有效性检查。
6. **知识复用与证据正确性仍是独立边界。** 新实例在相同payload与配置模型下实际选择已记录的清除覆盖/重启方法，修复后重新验收200。payload条件、配置模型、有效期变化分别使旧建议不返回。相同字节却可以支持两条作者声称相反的修正；知识包同时返回，实验明确转人工审查，不自动选择新记录。
7. **实际停止后的失败没有被转为成功。** 四路径在目标停止后都失败；B/C保留失败来源。所有lab资源停止。基线可以自己记录同样信息；本实验未证明额外信封是专有价值。

以上是本机真实Git、独立Node进程、文件、HTTP与Markdown的受控实验；不是生产事故、多机器、SSH凭据、远端身份认证、真实CI服务或LLM可靠性验证。

## 实验支持的推断与决策

- **描述、引用、执行、组合继续交给原生JS/ESM。** 不引入统一对象注册、字符串解析或新执行语言。本实验中删除三种候选层，核心工程任务仍成立，原生基线维护负担最低。
- **A不独立成包。** 它增加说明的发现投影，但WeakMap与描述同步没有优于普通模块导出的证据。说明可以仅放在需要提供给Agent的消费边界，不为每个普通函数声明。
- **B值得作为局部写法继续检验，不提升Core。** 价值是明确“这次观测属于谁、现在能否使用”，不是注册对象或统一任务。代价是subject声明、响应核对、事件存储和领域条件；本轮只是一组简单函数，原生基线也能照写。
- **C暂不继续投入透明投影方向。** 对变化的敏感性以隐藏语义成本换来；固定引用与动态引用需要消费者主动选择。普通getter/闭包也能动态解析，没有证据需要Proxy。
- **没有候选被证明总体优于原生基线。** 没有人工耗时基准，不声称降低接洽时间或提高Agent成功率。选择原生优先不是断言所有目录或观测机制都无价值。

| `@locus/tasks`、CLI、workspace适配 | 保留为可选显式调用工具与历史证据，不再将其执行信封视为所有消费者的必要入口；没有为本轮加任务 |

| 本轮三种候选 | 仅在实验13内存在，不发布新包、不改Core，不创建兼容层 |

这修正的是“发现和执行的统一入口自然导向更好的总体API”这一未证假设，不推翻[结论2的调用边界正确性](2-workspace-tasks.md)，也不重复以测试通过替代[结论3要求的工程价值](3-operational-experiments.md)。

## 尚未验证的设计假设

- 跨独立工程/独立作者重复出现的观测归属，可能值得共享小契约；目前只验证一个服务模型。
- Agent拿到原生模块+少量说明，可能已足够发现能力；本轮只证明可枚举内容，不证明实际Agent选择质量、权限遵守或新增适配成功率。
- B的实例/连接字段是否足够，取决于服务身份、执行视角、配置生命周期等领域条件。相同subject不保证状态未变化，前后检查不保证原子性，也不检测变化后恢复的ABA。
- 所有说明、实例声明、证据解释都来自可信协作代码；不防伪、不提供OS权限隔离。

## 下一步只检验一个问题

**在第二个独立工程任务中，原生模块加显式观测归属检查，是否会重复出现同一小契约，并实际减少一次可观察的错目标/旧证据误用，而不要求维护平行版本状态？**

优先以已有只读工具接入与第一任务不同的设施；对比手写原生检查与可选共享函数。若无重复收益，保留领域代码，不提炼包。不要先实现身份平台、任务引擎或依赖图。
