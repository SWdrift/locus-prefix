## 2. 历史思想交叉：不是功能选型

### 2.1 从导航结构到关系查询：联系未必是持久对象

Codd 1970年论文的原始动机是让消费者不必随数据表示/访问路径改变；[原始摘要与论文入口](https://dl.acm.org/doi/10.1145/362384.362685)。本轮该站全文403、两个PDF镜像分别抽取不完整/证书失败，因此不声称逐页复核原论文，具体查询语义以[SQLite SELECT文档](https://www.sqlite.org/lang_select.html)与实验16为据。

区别不在“对象换成行”：导航式消费需要先确定访问路径，关系式消费可以从事实集合推导当前关系。例如“有支持且没有反证的方法”由查询产生，不必逐项建立 `supports`/`blocks` 边或注册每个临时对象。

但 `NOT EXISTS` 只是在**当前数据库可见输入**中没有反证，绝非世界上没有反证。查询能消除派生边同步责任，不能消除事实摄取、领域键、范围和权限责任。SQLite成熟的单机事务可覆盖多连接，不能因此变成多主离线数据库、远程事务或领域知识引擎。

### 2.2 从电子表格到增量计算：依赖来自求值，不必手工声明图

[Vue reactivity机制说明](https://vuejs.org/guide/extras/reactivity-in-depth.html)以电子表格为出发点：读取属性时收集依赖，写入时使消费者失效。[miniAdapton论文第1–3节](https://arxiv.org/html/1609.05337v1)则从1968年的memoization传统出发，指出可变输入使普通缓存失效；保存 demanded computation graph，以接口内变更传播维持 from-scratch consistency。两者不是同一实现，也不将Adapton的形式保证直接归给Vue。

本轮还读取 Vue `computed.ts` [源码](https://github.com/vuejs/core/blob/v3.5.44/packages/reactivity/src/computed.ts)，以及安装版 `dist/reactivity.cjs.js` 的 `refreshComputed`：缓存更新依赖其收集到的依赖/版本，而非读取外部系统的所有变化。实验16验证SQLite写入是图外变化。

新的能力是“组合可继续随已摄取的变化更新”，不是自动发现外部真相。普通JS每次重算在此反例中同样正确；增量系统的价值要在多消费者、动态依赖与计算代价下评估，本轮没有测量性能收益。它增加图内状态、调试和摄取边界。

失败/撤回路线也有价值：[Vue Reactivity Transform](https://vuejs.org/guide/extras/reactivity-transform.html)在3.4被移除，意在减少 `.value`，但跨函数传递仍需区分值和ref并使用逃逸语法。它不是“响应式失败”，而是反驳“更接近普通变量语法就自然更流畅”。

### 2.3 从分布式数据一致性到程序单调性：共同历史不能抹去否定

[Keeping CALM](https://arxiv.org/html/1901.01930v1)第1–3节回顾2010年提出的CALM、后续形式化、Bloom/Dedalus：在其网络/输入模型中，可无协调得到一致程序结果的计算，恰是可表达为单调逻辑的计算。它讨论的是输出合流，不是“所有读都最新”或CAP中的线性一致。

关键反例不是“网络慢”：

- “存在支持证据”随追加事实可以保持成立。
- “存在支持且不存在反证，所以现在允许执行”在新事实加入时会被撤销。
- 将支持/反证全部改成append-only，只使**存储**增长单调，不会使这个**决策**单调。

CALM还给出建设性方向：购物期间合并与结算承诺分开；利用显式manifest限定输入而非假装全局已完整。迁移到本案例是**待验证假设**：探索可自由累积，某次执行则针对已约定的证据范围/版本承诺。不因此制造全局成员注册表，也不把某份manifest当未来永远无反证的证明。

实验16只演示一条具体非单调反例和本地串行化，不是对CALM的实验性证明。Bloom是研究语言路线，本轮未安装运行，不宣称其生产成熟度等同SQLite。

这一解释也必须接受反方：[Invariant confluence（2014）](https://www.vldb.org/pvldb/vol8/p185-bailis.pdf)第3–5节把问题改为“给定操作、不变量和merge，各自合法的分支合并后是否仍合法”，并明确约束写错/遗漏就不能保证业务正确。[Bounded counter（2015）](https://arxiv.org/html/1503.09052v1)第II–III节继承escrow思想，把可消耗权利分给副本，本地权利够时无需逐次全局协调，不够时拒绝或转移权利。因果一致与数值不变量在该文中是正交问题。这些是文献证据，未运行Riak或bounded-counter实现；它们提示“让有限操作天然保持不变量”是与“每次证明没有反证”不同的研究方向，不可被本轮反例排除。

### 2.4 其他竞争语义及其历史

[因果历史专题](causal-history-study.md)深入CRDT/Automerge及与Git/事件历史的区别；[执行专题](execution-history-study.md)深入构建、协调、持久工作流、能力/协议及失败的分布式透明性。共同的历史教训不是“统一有害”，而是**透明地跨过某条边界仍须有人支付该边界的语义责任**。

[Spritely/Goblins论文](https://files.spritely.institute/papers/spritely-core.html)提供不能被CORBA经验排除的反方：沿Scheme/W7和E的传统，以引用传递权限，明确区分near同步与far异步，用vat/transactional heap把一轮状态变更和待发送消息一起提交（第3.5–3.6节）。它不是靠少量说明给普通对象补授权，而是改变运行时语义来同时获得封装、局部事务和组合。论文仍标为draft，本轮没有运行Goblins，也不能把vat内事务外推到任意文件/网络副作用。复杂核心、分布式对象和JS以外的语言仍是有效竞争者。

另一个已核对的一手边界是[MCP 2025-11-25 Tasks](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks#task-cancellation)：它已有实验性的持久任务状态，而非只有即时tool call；有效取消请求要求状态变成cancelled，但只要求SHOULD尝试停止执行，即使执行继续完成，状态也必须保持cancelled。协议状态与真实副作用必须分别解释；这与实验16相互呼应，但本轮没有实现或运行MCP取消实验。

## 4. 四种实质竞争的构想

不是给同一注册表起四个名字。每种改变谁负责状态、历史、组合与失败；以下代码分别来自实际实验或明确标注的操作草图。

### A. 无中心的可检查组合：语言与协议即工作空间

事物仍是文件、模块、URL、现有工具。版本由Git/工具本身持有，知识为带来源的文档；Agent读取公开接口和源码，在任务时生成窄组合。无统一运行时、全局图或永久Locus对象身份。

实际实验16的原生消费：

```js
const native = () => decide(findings);
findings.push({ id: 'b', stance: 'refute' });
native(); // false；调用时重算，不保留自动更新缓存
```

能力来自临时可构造性；异构保持独立，共在成本低。反方：跨调用的变更通知、状态闭合与恢复由每个组合重新接洽。Agent可能生成正确代码，却不能在未知副作用的工具外补出exactly-once。何时足够：短生命、可重算/可人工检查的工作。新的普遍能力未证明，但它是不可省略的强基线，不是故意做弱的JSON覆写对照。

### B. 因果协作空间：可争议的知识本身可分叉

事物是共同CRDT文档中的值/操作；文件与设施仍在各自外部系统，用领域引用关联。知识支持离线编辑与合并，历史由Automerge维护；执行必须独立决策，不直接把map可见winner当授权。

实际消费详见实验15与专题中的 `clone/change/merge/getConflicts/save/load`。新能力是保留并发解释和可分叉过去，不要求作者先在线协调。代价是同源历史、冲突策略、历史体积与二进制持久化；JSON只够做展示，不够完整导出其保证。共在允许不同观点并存；流畅不能等于自动抹平冲突。失败方式：结构收敛而业务矛盾、合并后的可见值被误作唯一真理。

### C. 查询/变化驱动的决策空间：先推导，再限定承诺范围

事物是领域事实，不要求统一实体图；关系由查询产生，展示由reactive计算更新，历史/本地承诺可由数据库维护。人/Agent可以构造新查询，不必改每个资源类型。现有工具保持独立，摄取是显式责任。

实际实验16查询：

```sql
CREATE VIEW eligible AS
  SELECT DISTINCT s.procedure FROM findings s
  WHERE s.stance = 'support' AND NOT EXISTS (
    SELECT 1 FROM findings r
    WHERE r.procedure = s.procedure AND r.stance = 'refute'
  );
```

实际Vue消费揭示反例：

```js
const databaseComputed = computed(eligible);
const revision = ref(0);
const explicitBridge = computed(() => { revision.value; return eligible(); });
// 第二连接写入SQLite不触发Vue；摄取完成后revision.value++才使桥失效。
```

新增能力是无需显式派生边即可重组事实；代价是数据建模、导入、事务和失效信号。查询的闭世界假设碰到离线作者就失效；复杂核心能简化本地决策，不等于端到端安全。

### D. 外部引擎主导的可重放工作：语言是前端而非世界模型

资源由构建/协调器持有，流程由持久执行引擎持有；知识与证据用引用关联，不强制存进流程事件。人/Agent构造受引擎约束的描述和Activity，而不是执行任意闭包。具体Nix/Temporal消费与未运行边界见执行专题。

潜在新增能力是可重放的控制流、显式构建输入、跨worker恢复，而不是更短函数调用。代价是服务部署、确定性/版本约束、provider/Activity适配、幂等性和历史维护；没有本机运行，不能与A宣称成本赢家。复杂引擎是强竞争者，不因违反简单Core偏好被排除。

## 5. 先选反例，再选代码

选择两条最可能改变方向的分歧：

1. **可见快照是否足以表达并发修订？** 实验15使用成熟Automerge，与明确丢历史的快照对照；不是把差的手写merge当所有原生方案。必须同时保留失败判断：CRDT收敛不等于可安全执行。
2. **派生关系/响应式更新是否足以维持可执行判断？** 实验16用原生重算、Vue 3.5.44及Node内置SQLite 3.53.3，检验图内变化、图外变化、本地事务与外部动作四条边界。

没有建立任务目录、身份注册表、统一图或DevOps工作台。实验生成的匿名事实与文件副作用是语义探针，不伪装生产事故。没有运行分布式协议、真实网络分区或远程执行器。

## 6. 实验16实际观察与保留的失败方案

命令：`node tests/16-derived-decisions/scenario.js`；断言入口：`node --test tests/16-derived-decisions/demo.test.js`。实验临时数据库与actuator文件位于工作区 `temp/`，关闭连接后清理。输出字段为观察摘要，不是持久工作台API。

| 试探判断 | 实际观察 | 修正及影响 |
| --- | --- | --- |
| 保存一次可执行判断即可复用 | 追加反证后，快照仍true，普通重算/Vue变false | 快照只回答过去；原生函数并非必须升级成reactive才正确 |
| computed包住查询即可自动跨系统传播 | 第二连接提交反证后，直接SQL为空，computed仍含repair | 图外变化需摄取信号；显式revision桥发信号后为空。不是Vue缺陷，也不能用增加Proxy挽救所有外部工具 |
| 数据只追加就无需协调授权 | support→加入refute使eligible撤回 | 非单调的是决策，不是存储；不能把append-only/CRDT与安全授权画等号 |
| SQLite事务可以让后到反证阻止已接纳但未执行的动作 | BEGIN IMMEDIATE时第二writer被SQLITE_BUSY拒绝；先提交的intent为1，反证后新intent为0；旧intent仍实际生成 `executed:repair` 文件 | 本地接纳串行化不实现这一撤销契约。实验特意不加重查来掩盖边界；重查也不消除执行前最后窗口 |

这里的锁失败是预期的并发机制，不作为库缺陷；旧intent副作用是相对于上述撤销契约的失败方案，而不是所有授权模型下都不合法。若接纳时授予不可撤销、限目标/限额的权利，反证仅阻止新grant，旧intent完成可以完全符合契约。**证据足够与权利仍有效是两个问题**；不能从非单调查询推出所有动作必须全球协调。未测吞吐/延迟、无长期维护排名。SQL表只含procedure/stance，省略作者认证、适用环境、证据哈希、时间等；它不是比实验14更安全的替代产品。

## 7. 新研究方向，而非冻结范式

**候选新表达方向：可分叉探索与有界承诺分开。** 探索层允许多作者并发事实/解释，查询层给出针对可见证据的推导，动作层只对明确范围、版本和执行器契约负责。不是声称发明了CRDT、CALM、事务或工作流；新的项目认识是将它们作为互不替代的能力组合，而非围绕原生对象补同一种元信息。

这一方向尚有真正矛盾：

- 允许未协调作者离线共在，就不能把局部“无反证”当全球执行许可；要求所有人先在线又损害流畅。应检验局部权限/有限证据范围是否足够，而非默认全局真相。
- 保留所有分歧利于追溯，却可能使行动长期阻塞；自动选winner提高连续性，却丢失解释和风险。需要领域仲裁，而非通用“最新即真”。
- 联邦保留各自历史，但查询需要关联版本；关联本身可能形成新同步债务。单一引擎能简化局部责任，却要求迁移语义。

下一项最高价值实验：把实验15的离线反证在实验16本地intent提交前后分别送达，再用一个**支持版本前提的真实领域执行器**对照不支持者，检验范围承诺/冲突解决是否改变动作，而不是继续增加知识记录字段。该执行器尚未选择/运行，本轮不宣称端到端解决。另一个不同方向是运行现成持久工作流的崩溃恢复，检验其历史与知识修订如何分离；不以手写日志替代Temporal。
